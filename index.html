        Built with Kiro

        This board was built spec-first in Kiro. The requirements, design, and task list live in .kiro/specs/afterlife-bbs/; .kiro/steering/ holds the product and tech rules every change must respect; two hooks run the logic checks on save and the smoke test before commit; and a custom agent defines the Séance matcher. Kiro CLI 3.4.0 is installed on the build machine. No MCP servers were used — the app needs no external data, so there was nothing to connect.

        One feature, traced end to end — the Séance matcher: REQ-18 in requirements.md → findHelpers() in app.js → the “These neighbours might help you” card → property checks in tests/checks.mjs → agent rules in .kiro/agents/seance-matcher.md. Everything above is inspectable in the repo: github.com/zonglinc00-debug/afterlife-bbs/tree/main/.kiro

        House rules

        1. Ten posts per page. When you reach the end, the board says so — then go for a walk.
        2. One candle per browser per post — this browser remembers which notes you lit. Light it if a post warmed the room; take it back if you change your mind.
        3. From midnight to 6am the board rests. Read all you like; posting waits for morning. The rest is a house rule enforced in this browser only — a shared norm, not a server lock.
        4. Be a neighbour first. No follower counts, no ads, no ranking. Newest first, always — and today's digest makes sure a good note doesn't get buried.
        5. Your board lives only in your browser — no server, no account. Export it any time and take it with you; anyone can open the file with Import.

        How the Séance Circle works

        Post a request and pick a category. The board looks through past offers from your neighbours and shows you who might be able to help — neighbours who posted an offer in the same category, one entry per neighbour, newest offer first. All matching happens on your own device — nothing leaves this browser.
